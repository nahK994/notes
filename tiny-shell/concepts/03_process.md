## Process: একটা Program যখন জীবন্ত হয়ে ওঠে

তোমার disk-এ `/bin/ls` পড়ে আছে।

নিরীহ একটা file। কিছু করছে না, কাউকে বিরক্ত করছে না। তুমি terminal-এ `ls` টাইপ করার আগ পর্যন্ত সে ঘুমিয়েই থাকে।

তুমি Enter চাপলে কী হয়?

সেই ঘুমন্ত file-টা হঠাৎ জীবন্ত হয়ে ওঠে। RAM-এ জায়গা নেয়, CPU-র সময় চায়, screen-এ কথা বলে। এই জীবন্ত সত্তাটাই **Process**।

```
DISK-এ:                         RAM-এ (চলার সময়):
────────                        ──────────────────
/bin/ls                         Process (PID 1234)
  │                               │
  │ একটা file                     │ জীবন্ত, চলছে
  │ ঘুমাচ্ছে                      │ CPU খাচ্ছে
  │ কিছু করছে না                  │ memory দখল করেছে
  │
  └── recipe বইয়ের মতো          └── সেই recipe-তে রান্না হচ্ছে
```

**Program** = recipe — disk-এ লেখা থাকে, নিজে কিছু করে না।
**Process** = সেই recipe অনুযায়ী রান্না — RAM-এ চলছে, কাজ করছে।

একটা সুন্দর দিক হলো — একই recipe দিয়ে একসাথে অনেক রান্না হতে পারে। তুমি ৫টা terminal-এ `ls` চালালে ৫টা আলাদা process তৈরি হয়। প্রত্যেকের আলাদা PID, আলাদা memory — কিন্তু সবার জন্ম একই `/bin/ls` file থেকে।

---

### কেন Process দরকার?

Process না থাকলে একটা program চললে অন্যটা চলতে পারতো না। তোমাকে Firefox বন্ধ করে তারপর music player খুলতে হতো। কিছু download হওয়ার সময় পুরো computer আটকে থাকতো।

Process-এর কারণে এটা সম্ভব হয়:

```
একই সময়ে:
┌────────────┐   ┌────────────┐   ┌────────────┐
│  firefox   │   │  terminal  │   │   music    │
│  PID: 1001 │   │  PID: 1002 │   │  PID: 1003 │
│            │   │            │   │            │
│  নিজের     │   │  নিজের     │   │  নিজের     │
│  memory    │   │  memory    │   │  memory    │
└────────────┘   └────────────┘   └────────────┘
      ↑                ↑                ↑
      └────────────────┴────────────────┘
               CPU share করছে
          (এত দ্রুত switch করে যে
           মনে হয় একসাথে চলছে)
```

প্রতিটা process আলাদা দ্বীপের মতো — নিজের memory, নিজের state। একজনের crash অন্যজনকে সাধারণত টেনে নামায় না। Firefox হ্যাং করলে তোমার music থামে না।

---

### Process-এর ভেতরে কী থাকে?

Process মানে শুধু "চলছে" না। Kernel প্রতিটা process-এর জন্য RAM-এ একটা সাজানো বাড়ি বানিয়ে দেয় — কয়েকটা আলাদা ঘর নিয়ে:

```
Process (PID: 1234) — RAM-এ যা থাকে:
┌──────────────────────────────────────────┐
│                                          │
│  Code Segment                            │
│  ┌────────────────────────────────────┐  │
│  │ program-এর instructions           │  │
│  │ (machine code, read-only)          │  │
│  └────────────────────────────────────┘  │
│                                          │
│  Stack                         ↕ grows   │
│  ┌────────────────────────────────────┐  │
│  │ function call history             │  │
│  │ local variables                   │  │
│  │ main() → runShell() → execute()   │  │
│  └────────────────────────────────────┘  │
│                                          │
│  Heap                          ↕ grows   │
│  ┌────────────────────────────────────┐  │
│  │ dynamic memory                    │  │
│  │ (নতুন data তৈরি হলে এখানে জমে)   │  │
│  └────────────────────────────────────┘  │
│                                          │
│  File Descriptors                        │
│  ┌────────────────────────────────────┐  │
│  │ FD 0 → keyboard                   │  │
│  │ FD 1 → screen                     │  │
│  │ FD 2 → screen (error)             │  │
│  └────────────────────────────────────┘  │
│                                          │
│  Environment Variables                   │
│  ┌────────────────────────────────────┐  │
│  │ PATH=/usr/bin:/bin                │  │
│  │ HOME=/home/user                   │  │
│  └────────────────────────────────────┘  │
└──────────────────────────────────────────┘
```

**Code Segment** — program-এর instructions। Read-only, চলার সময় বদলায় না। একই `/bin/ls` থেকে জন্ম নেওয়া ৫টা process এই অংশটা share করতে পারে — আলাদা করে copy রাখার দরকার নেই।

**Stack** — function call হলে এখানে জমা হয়। `main()` → `runShell()` → `execute()` — এই chain এখানে থাকে। Function শেষ হলে stack থেকে মুছে যায়, স্বয়ংক্রিয়ভাবে। তোমাকে কিছু করতে হয় না।

**Heap** — তুমি যখন নতুন data তৈরি করো, সেটা এখানে জমে। Stack-এর মতো automatically মুছে যায় না। Go-তে garbage collector এটা manage করে। C-তে তোমাকে নিজেই `free()` করতে হয় — না করলে সেটা **memory leak**, যা ধীরে ধীরে তোমার program-কে ভেতর থেকে ফাঁপা করে দেয়।

**File Descriptors** — process বাইরের জগতের সাথে যেভাবে কথা বলে। আগের chapter-এ বিস্তারিত দেখেছো।

**Environment Variables** — `PATH`, `HOME` ইত্যাদি। Child process এগুলো parent থেকে copy করে পায়। তাই তুমি terminal-এ যে `PATH` set করো, সেখান থেকে চালানো সব command সেটা পায় — কোনো আলাদা কাজ ছাড়াই।

### Process-এর জীবনচক্র

প্রতিটা process জন্মায়, কাজ করে, মরে। কিন্তু মাঝখানে বেশ কিছু অবস্থা আছে:

```
                   fork() — জন্ম
                       │
                       ▼
                  ┌─────────┐
                  │ CREATED │ ← সবে তৈরি হলো
                  └────┬────┘
                       │ ready হলো
                       ▼
                  ┌──────────┐
         ┌───────►│ RUNNABLE │ ← চলার জন্য ready,
         │        └────┬─────┘   কিন্তু CPU পাচ্ছে না
         │             │ CPU পেলো
         │             ▼
         │        ┌─────────┐
         │        │ RUNNING │ ← এখন সত্যিই চলছে
         │        └────┬────┘
         │             │
         │      ┌──────┴───────┐
         │      │              │
         │      ▼              ▼
         │  ┌─────────┐   ┌────────┐
         └──│ WAITING │   │ ZOMBIE │
            └────┬────┘   └───┬────┘
                 │            │
           I/O শেষে     parent wait()
           RUNNABLE-এ   করলে
           ফিরে যায়         │
                             ▼
                         ┌──────┐
                         │ DEAD │ ← সম্পূর্ণ মুছে গেছে
                         └──────┘
```

**RUNNING** — CPU-তে এই মুহূর্তে সত্যিই চলছে। যেকোনো সময়ে একটা CPU core-এ একটাই process RUNNING হতে পারে।

**RUNNABLE** — চলার জন্য তৈরি, কিন্তু CPU অন্য কারো সাথে ব্যস্ত। অপেক্ষার লাইনে দাঁড়িয়ে। Linux এত দ্রুত switch করে যে আমরা টের পাই না।

**WAITING** — কোনো কিছুর জন্য আটকে আছে। `ls` যখন disk থেকে file list পড়ে, সেই মুহূর্তে সে CPU ছেড়ে WAITING-এ চলে যায়। Disk পড়া শেষ হলে আবার RUNNABLE। এই ফাঁকে অন্য process CPU পায় — এভাবেই Linux একসাথে হাজার process চালায়, আসলে একটার পর একটা করে।

### Zombie Process: মৃত, কিন্তু তালিকায় আছে

নামটা ভয়ের। ব্যাপারটা আসলে সহজ।

তোমার বন্ধু বললো, "আমি কাজ শেষ করে তোমাকে result জানাবো।" বন্ধু কাজ শেষ করলো, কিন্তু তুমি এখনো জিজ্ঞেস করোনি। সে technically কাজ শেষ — কিন্তু result হাতে নিয়ে তোমার জন্য দাঁড়িয়ে আছে। না পুরোপুরি বেঁচে, না পুরোপুরি চলে গেছে।

Process-এ ঠিক এটাই হয়:

```
Shell (parent)                    ls (child)
──────────────                    ──────────
ls চালালো              →          কাজ শুরু করলো
                                  কাজ শেষ করলো
                                  exit(0) করলো
                                       │
                                       │ "আমার exit code
                                       │  কেউ নিলো না"
                                       ▼
                                  ZOMBIE 🧟
                                  (RAM-এর বেশিরভাগ
                                   free, কিন্তু
                                   process table-এ
                                   entry আছে)
Shell (parent):
wait() করলো            ←          exit code দিলো
"ls সফল হয়েছে"                    DEAD — সম্পূর্ণ গেছে
```

Zombie নিজে খুব কম resource নেয় — শুধু process table-এ একটা row। কিন্তু হাজারটা zombie জমলে সেই table ভরে যায়। নতুন process বানানো যায় না। পুরো system নতুন কাজ করতে পারে না।

সমাধান সহজ — parent সবসময় `wait()` করবে। Child শেষ হলে তার exit code নেবে, তাহলেই zombie সাথে সাথে মুছে যায়।

### PID এবং PPID: প্রতিটা Process-এর পরিচয়

প্রতিটা process-এর দুটো পরিচয়:

```
PID  = নিজের নম্বর (Process ID)
PPID = parent-এর নম্বর (Parent Process ID)
```

Linux boot হওয়ার পর থেকে একটা বংশতালিকা তৈরি হতে থাকে:

```
PID 1: systemd  (সবার পূর্বপুরুষ)
├── PID 450: login
│   └── PID 890: bash
│       └── PID 1234: tiny-shell   ← আমাদের shell
│           └── PID 1235: ls       ← shell-এর child
└── PID 512: sshd
```

Linux-এ প্রতিটা process-এর একটা parent আছে। এই গাছ একদম উপরে গেলে PID 1-এ পৌঁছায় — `systemd`, যাকে kernel নিজে boot-এর সময় তৈরি করে। সে কারো child না, সবার পূর্বপুরুষ।

নিজে দেখতে চাইলে:

```bash
echo $$        # তোমার shell-এর PID
echo $PPID     # তোমার shell-এর parent PID
pstree -p $$   # পুরো বংশগাছ দেখো
```

`pstree` চালালে দেখবে তুমি নিজেও এই গাছের একটা পাতা। `systemd` থেকে তোমার terminal পর্যন্ত একটা সরল রেখা আছে — প্রজন্মের পর প্রজন্ম।

---

Program হলো blueprint। Process হলো সেই blueprint অনুযায়ী তৈরি জীবন্ত সত্তা।

Kernel সেই সত্তার জন্মদাতা, রক্ষক — এবং প্রয়োজনে, মৃত্যুদূত।
